To debug issues with OC Nano, start by checking the logs and local data it stores on disk.

---

## Logs

CLI and server logs are written to:

- **macOS/Linux**: `~/.local/share/ocnano/log/ocnano.log`
- **Windows**: Press `WIN+R` and paste `%USERPROFILE%\.local\share\ocnano\log`

Logs are appended to `ocnano.log`. Run `ocnano debug paths` to find the log directory if you use custom XDG paths.

You can set the log level with the `--log-level` command-line option to get more detailed debug information. For example, `ocnano --log-level DEBUG`.

---

## Storage

ocnano stores session data and other application data on disk at:

- **macOS/Linux**: `~/.local/share/ocnano/`
- **Windows**: Press `WIN+R` and paste `%USERPROFILE%\.local\share\ocnano`

This directory contains:

- `auth.json` - Authentication data like API keys, OAuth tokens
- `log/` - Application logs
- `ocnano.db` - SQLite database containing projects, sessions, and messages
- `snapshot/` - Project snapshots used for undo

Run `ocnano db path` to find the active database. Custom `OCNANO_DB` settings and development channels can use a different filename.

---

## Uninstall

To uninstall the OC Nano CLI and remove its related files, run:

```bash
ocnano uninstall
```

The command shows what will be removed and asks for confirmation. See the [CLI reference](/docs/cli#uninstall) for options to keep your configuration or application data.

To remove OC Nano Desktop, uninstall the application through your operating system's app management tools.

---

## Desktop app

OC Nano Desktop uses Electron and runs a local OC Nano server in the background. Most issues are caused by a misbehaving plugin, a corrupted cache, or a bad server setting.

Desktop logs are stored in timestamped directories under `logs/` in the [desktop app data directory](#reset-desktop-app-storage-last-resort).

### Quick checks

- Fully quit and relaunch the app.
- If the app shows an error screen, click **Restart** and copy the error details.
- macOS only: `OC Nano` menu -> **Reload Webview** (helps if the UI is blank/frozen).

---

### Disable plugins

If the desktop app is crashing on launch, hanging, or behaving strangely, start by disabling plugins.

#### Check the global config

Open your global config file and look for a `plugin` key.

- **macOS/Linux**: `~/.config/ocnano/ocnano.jsonc` (or `~/.config/ocnano/ocnano.json`)
- **macOS/Linux** (older installs): `~/.local/share/ocnano/ocnano.jsonc`
- **Windows**: Press `WIN+R` and paste `%USERPROFILE%\.config\ocnano\ocnano.jsonc`

If you have plugins configured, temporarily disable them by removing the key or setting it to an empty array:

```jsonc
{
  "$schema": "https://opencode.ai/config.json",
  "plugin": [],
}
```

#### Check plugin directories

OC Nano can also load local plugins from disk. Temporarily move these out of the way (or rename the folder) and restart the desktop app:

- **Global plugins**
  - **macOS/Linux**: `~/.config/ocnano/plugins/`
  - **Windows**: Press `WIN+R` and paste `%USERPROFILE%\.config\ocnano\plugins`
- **Project plugins** (only if you use per-project config)
  - `<your-project>/.ocnano/plugins/`

If the app starts working again, re-enable plugins one at a time to find which one is causing the issue.

---

### Clear the cache

If disabling plugins doesn't help (or a plugin install is stuck), clear the cache so OC Nano can rebuild it.

1. Quit OC Nano Desktop completely.
2. Delete the cache directory:

- **macOS**: Finder -> `Cmd+Shift+G` -> paste `~/.cache/ocnano`
- **Linux**: delete `~/.cache/ocnano` (or run `rm -rf ~/.cache/ocnano`)
- **Windows**: Press `WIN+R` and paste `%USERPROFILE%\.cache\ocnano`

3. Restart OC Nano Desktop.

---

### Fix server connection issues

OC Nano Desktop can either start its own local server (default) or connect to a server URL you configured.

If you see a **"Connection Failed"** dialog (or the app never gets past the splash screen), check for a custom server URL.

#### Clear the desktop default server URL

From the Home screen, click the server name (with the status dot) to open the Server picker. In the **Default server** section, click **Clear**.

#### Remove `server.port` / `server.hostname` from your config

If your `ocnano.json(c)` contains a `server` section, temporarily remove it and restart the desktop app.

#### Check environment variables

If you have `OCNANO_PORT` set in your environment, the desktop app will try to use that port for the local server.

- Unset `OCNANO_PORT` (or pick a free port) and restart.

---

### Linux: Wayland / X11 issues

On Linux, some Wayland setups can cause blank windows or compositor errors.

- Try launching under an X11 session to check whether the issue is specific to Wayland.

---

### Windows: General performance issues

If you're experiencing slow performance, file access issues, or terminal problems on Windows, try using [WSL (Windows Subsystem for Linux)](/docs/windows-wsl). WSL provides a Linux environment that works more seamlessly with OC Nano's features.

---

### Notifications not showing

OC Nano Desktop only shows system notifications when:

- notifications are enabled for OC Nano in your OS settings, and
- the app window is not focused.

---

### Reset desktop app storage (last resort)

If the app won't start and you can't clear settings from inside the UI, reset the desktop app's saved state.

1. Quit OC Nano Desktop.
2. Find and delete these files (they live in the OC Nano Desktop app data directory):

- `ocnano.settings` (desktop settings, including the default server URL)
- `ocnano.global.dat` and `ocnano.workspace.*.dat` (UI state like recent servers/projects)

For the stable release, the desktop app data directory is:

- **macOS**: `~/Library/Application Support/ai.ocnano.desktop/`
- **Linux**: `~/.config/ai.ocnano.desktop/` (or `$XDG_CONFIG_HOME/ai.ocnano.desktop/`)
- **Windows**: `%APPDATA%\ai.ocnano.desktop\`

Beta and development builds use the `ai.ocnano.desktop.beta` and `ai.ocnano.desktop.dev` directories instead.

## Common issues

Here are some common issues and how to resolve them.

---

### OC Nano won't start

1. Check the logs for error messages
2. Try running with `--print-logs` to see output in the terminal
3. Ensure you have the latest version with `ocnano upgrade`

---

### Authentication issues

1. Try re-authenticating with the `/connect` command in the TUI
2. Check that your API keys are valid
3. Ensure your network allows connections to the provider's API

---

### Model not available

1. Check that you've authenticated with the provider
2. Verify the model name in your config is correct
3. Some models may require specific access or subscriptions

If you encounter `ProviderModelNotFoundError` you are most likely incorrectly
referencing a model somewhere.
Models should be referenced like so: `<providerId>/<modelId>`

Examples:

- `openai/gpt-6.1-sol`
- `openrouter/google/gemini-3.8-flash`
- `ocnano/kimi-k2`

To figure out what models you have access to, run `ocnano models`

---

### ProviderInitError

If you encounter a ProviderInitError, you likely have an invalid or corrupted configuration.

To resolve this:

1. First, verify your provider is set up correctly by following the [providers guide](/docs/providers)
2. If the issue persists, try clearing your stored configuration:

   ```bash
   rm -rf ~/.local/share/ocnano
   ```

   On Windows, press `WIN+R` and delete: `%USERPROFILE%\.local\share\ocnano`

3. Re-authenticate with your provider using the `/connect` command in the TUI.

---

### AI_APICallError and provider package issues

If you encounter API call errors, this may be due to outdated provider packages. ocnano dynamically installs provider packages (OpenAI, Anthropic, Google, etc.) as needed and caches them locally.

To resolve provider package issues:

1. Clear the provider package cache:

   ```bash
   rm -rf ~/.cache/ocnano
   ```

   On Windows, press `WIN+R` and delete: `%USERPROFILE%\.cache\ocnano`

2. Restart ocnano to reinstall the latest provider packages

This will force ocnano to download the most recent versions of provider packages, which often resolves compatibility issues with model parameters and API changes.

---

### Copy/paste not working on Linux

Linux users need to have one of the following clipboard utilities installed for copy/paste functionality to work:

**For X11 systems:**

```bash
apt install -y xclip
# or
apt install -y xsel
```

**For Wayland systems:**

```bash
apt install -y wl-clipboard
```

**For headless environments:**

```bash
apt install -y xvfb
# and run:
Xvfb :99 -screen 0 1024x768x24 > /dev/null 2>&1 &
export DISPLAY=:99.0
```

ocnano will detect if you're using Wayland and prefer `wl-clipboard`, otherwise it will try to find clipboard tools in order of: `xclip` and `xsel`.
